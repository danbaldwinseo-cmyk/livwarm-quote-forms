The Starting Point

What we reviewed

Four existing flows. Two competing apps.
One clear direction.

The current LivWarm forms — deals.livwarm.co.uk

Built in Cornerstone / WordPress. Step-based wizard with branching logic, postcode lookup, satellite map, product selection, finance calculator and contact capture. Google Maps API already active. GTM firing. But the execution falls short — broken placeholder copy, no trust signals early in the journey, the product presentation screen has no visible price above the fold, and the mascot/celebratory tone is mismatched for a £7,000+ purchase.

The UKEM app — app.ukem.co.uk

A React single-page application — the same architecture we'll use. Clean, functional and well-structured. 9 steps covering qualification, property details, electricity usage, battery placement, EV ownership, address/roof confirmation, product recommendation, upsell modal, contact capture, date selection and payment. The flow is thorough but cold — no trust signals, clinical design, financial data buried below the fold, payment screen premature for this price point.

Common architecture confirmed

Both the UKEM app and the recommended LivWarm rebuild use React SPAs embedded in a page. The UKEM URL structure (?product=solar) confirms a single app handling all four products via routing — exactly the pattern we'll follow. The Google Maps Satellite API is already licensed and in use on LivWarm.

The four flows reviewed

Solar & Battery

Priority 1

Most complex flow. Roof type, electricity usage, battery placement, EV qualification, satellite map, multi-tier product selection, finance calculator. The upsell modal (BUS grant / panel upgrade / warranty) is a key revenue mechanism.

UKEM — What Works

Features worth replicating

UKEM has solved some real problems.
We borrow the best, then go further.

✓

Answer breadcrumb trail

Previous answers stack above each new question as pill badges. Reassures users their inputs are recorded and lets them see their journey at a glance without going back. The current LivWarm forms have nothing equivalent.

✓

Friction reducers on hard questions

"I'm not sure" as a valid answer on battery location removes a common abandonment point. "Apply national kWh average (4,100 / 26.35p)" on the electricity usage screen is brilliant — lets users proceed without hunting for their bill. Both must be replicated.

✓

Help modal with annotated bill image

The "How to find your rates" modal shows a real EDF bill with arrows pointing to the unit rate and annual usage fields. More effective than any amount of copy. Worth replicating with a more brand-consistent design.

✓

Satellite roof map confirmation

Dropping a pin on your actual roof via Google Maps Satellite makes the quote feel real and property-specific. The Google Maps API is already licensed on LivWarm — no additional cost to include this. A moveable pin adds complexity for minimal benefit; a static confirmed view is sufficient.

✓

EV question within the solar flow

Asking "Do you have an electric vehicle?" inside the solar journey qualifies leads for the EV charger product simultaneously. Smart cross-sell with no added friction.

✓

Post-conversion upsell modal

The "Enhance Your System" modal after product selection offers panel upgrade, extended warranty and the BUS heat pump grant. Keeps the primary flow clean while capturing upsell revenue. The orange grant highlight card converts the solar journey into a heat pump lead at zero friction.

✓

QR code for property photos

After booking confirmation, a QR code links to a photo submission flow. Defers photo collection to post-conversion, avoids mid-form friction, sends link via email/SMS, gives 14 days. Genuinely clever — and it improves lead quality for the installer without impeding the conversion.

✓

Date picker with honest expectations

"Our team will confirm availability after your technical review" sets honest expectations while still capturing a preferred date as a micro-commitment. The phrasing reduces post-submission anxiety without underselling the commitment.

UKEM — What to Improve On

Where LivWarm can clearly do better

Functional but cold. Data-rich but buried.
Every weakness is an opportunity.

No trust signals anywhere in the early flow

Not one MCS badge, accreditation logo or partner brand appears until the booking summary page — step 6 of 9. For a £9,000+ purchase this is a serious omission. Trust must be established from step 1, not after the user has already committed.

The financial data appears too late

£40,931 vs £14,823 over 20 years. £26,108 total saving. 8-year break-even. These are the most persuasive numbers in the entire flow — and they appear below the fold on step 6, after the user has already committed to a product. They should be above the fold on the quote presentation screen where the buying decision is actually made.

Quote screen layout fights itself

The two-column layout on the product screen places financial analysis left and product tiers right, with no clear reading hierarchy. The satellite map thumbnail wastes a third of the above-the-fold area with no value at this stage. The tier selector (Recommended / Performance / Essential / Custom) looks like a contents list — not clickable product cards.

Price is too small and too passive

£9,095 appears in small header text and again quietly in the card. For a purchase this size, the price should be displayed confidently and in context — "£9,095 or from £97/month" should be a headline, not a detail. Hiding the price suggests uncertainty about it.

Design is clinical and cold

Plain white backgrounds, thin blue progress line at the very top of the screen, no visual warmth anywhere. The UKEM flow looks like internal software. LivWarm has a genuinely warm brand — the rebuild should feel like LivWarm, not a generic SaaS tool.

Contact details collected in a modal

Floating a contact form as an overlay on top of the quote screen strips away all visual context at the exact moment the user is committing their personal details. A dedicated full-screen step with a compact product/price summary visible at the top performs better.

Payment screen is premature

Presenting a Stripe checkout for £9,095 on a first visit — before a survey, a conversation, or a confirmed date — looks like high-pressure sales, not a professional service. The commitment LivWarm wants is a date in the diary. The payment option should be removed from the initial flow entirely.

Weak card interaction states

Default cards are flat. Hover raises the shadow. Selected fills blue. The interaction lacks physical satisfaction — it doesn't feel like pressing a button. The LivWarm rebuild will use a raised-by-default, sinks-on-press, highlights-on-select interaction that is noticeably more tactile and premium.

Redesigning the Quote Screen

The most important screen in the flow

Everything the user needs to decide.
Above the fold. No scrolling required.

New quote screen — reading order

1
The hook — personalised recommendation
"Based on your home, we recommend this system." Package name, panel count, battery, and price as a headline — large and confident. "£9,095 or from £97/month" is a statement of value, not a detail to find.
2
The numbers that matter
Three big scannable figures: monthly saving, 20-year total saving, break-even year. Positioned immediately below the price. Readable in two seconds. This is where the decision is made — these numbers do the selling.
3
The tier selector — four interactive cards
Essential / Recommended / Performance / Custom. Each is a fully interactive card using the raised-default, sinks-on-press, highlights-on-select interaction pattern. Selecting a tier updates the price and savings figures live. No collapsed rows, no ambiguous "Compare" links.
4
Trust and continuation
MCS Certified, HIES badge, partner logos (Aiko, Fox ESS, Tesla), then a single prominent "Continue with this system" button. No satellite map. No competing columns.

Why the map comes off the quote screen

The satellite view earns its place in the address confirmation step — it makes the quote feel property-specific and real. On the quote screen it serves no purpose. The user confirmed their address one step ago. Removing it recovers a third of the above-the-fold area and allows all decision-critical content to sit in a single view without scrolling.

Live price update as tiers are selected

When the user switches from Recommended to Essential, the price headline, monthly figure, and savings numbers all update simultaneously with a smooth transition. This makes the trade-off tangible and immediate — the user can feel what they're gaining or saving by choosing a different tier. No page reload, no navigation away from the screen.

The commitment step — before contact details

Before asking for name, email and phone, we show a "Confirm your selection" micro-step — a brief summary of what they've chosen with a single "This looks right — get my full quote" button. This micro-commitment anchors the user to their choice and significantly improves lead quality. People who confirm actively are higher-intent than people who passively fill in a form.

Card Interaction Design

How the answer cards will feel

Raised by default. Sinks on press.
Locks in with a pulse. Like a real button.

① Default

🏠

Detached

Visible shadow gives a raised, "pressable" feel. The card looks pickable before the user even hovers.

② Hover

🏠

Detached

Shadow reduces, card drops 2px. Responds to cursor weight before the click. Already feels like it's being pressed.

③ Active (80ms)

🏠

Detached

Shadow collapses fully. Card drops another 2px. The physical "press" moment — lasts 80ms, long enough to register on touchscreens.

④ Selected

🏠

Detached

Springs back with brand colour fill and border. Subtle 1.02 scale pulse confirms selection. Satisfying and definitive.

Mobile touch consideration

On touchscreens there is no true hover state — active and selected happen near-simultaneously. The active state duration is set to a minimum of 80ms in JavaScript to ensure the press feedback is perceptible before the selected state takes over. Without this, touch feels unresponsive.

Scale pulse ceiling

The selection scale is capped at 1.02. Beyond that, multiple cards scaling simultaneously on a grid looks chaotic rather than confirmatory. The pulse is a signal, not a celebration — subtle is correct.

Technical Build Plan

How we build it

React SPA in VS Code with Claude Code.
Token-efficient. Files on your machine.

Architecture

Single React app, four products via routing

One codebase in the livwarm-quotes folder. URL parameter (?product=solar) controls which flow loads. Shared components (card, progress bar, address lookup, finance calculator) used across all four products. No duplication.

Pricing via JSON — manageable without code

All product pricing, panel counts, battery options and tier definitions live in a pricing.json file derived from the spreadsheets. Prices change without touching the React code — just update the JSON. Can be extended to a simple spreadsheet-to-JSON export workflow.

WordPress deployment via Code Snippets plugin

The React app builds to a single JS bundle. A WordPress page uses a <div id="livwarm-quote"></div> mount point. The bundle is enqueued via the Code Snippets plugin. No theme editing, no FTP required for updates.

Payaca integration on submission

On form submission, a POST request fires to Payaca via their OpenAPI (Scale plan) or via a Zapier webhook (lower plans). Lead arrives in Payaca with full quote detail — product selected, tier, price, property info — not just contact fields.

Session workflow

Work in short, focused sessions

Each Claude session has one clear deliverable — qualification steps, quote screen, pricing logic, Payaca integration. Complete it, save to disk, end the session. This keeps token usage low and code quality high. Long sessions degrade context and produce errors.

Master code lives on your machine — not in chat

Claude Code in VS Code reads and writes files directly. You never paste large code blocks into chat. At the start of each session, Claude Code reads only the relevant file section. Token cost per edit is a fraction of a full-file chat edit.

This Project carries the context

Brand assets, pricing data, flow spec and session handover notes live in this Claude Project. Each new session starts informed without rehashing decisions already made. No token cost for re-explaining the brief.

Build order — solar first, then template for the rest

Solar is the most complex flow and the commercial priority. Once it's built and deployed, the EV, heat pump and boiler flows reuse the same component library, card interaction system, address lookup and finance calculator. The last three flows are significantly faster to build than the first.
